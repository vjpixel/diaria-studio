- **Exit 0** — ler `pulled[]` do JSON. Não vazio = o editor editou o doc e a edição foi gravada no(s) arquivo(s), preservando byte a byte o que não mudou: tratar exatamente como um `ajustar` já aplicado (§4d.1 a partir do passo 2 — xml check, cascata de título/lead se couber, re-render + re-serve + re-publish do Artifact do(s) preview(s) afetado(s), checks pós-edição) ANTES de apresentar, e incluir no resumo a linha `📝 Edições do doc puxadas: {pulled[]}` seguida de `pulled_changes.{file}.lines` (o diff `-`/`+` de cada arquivo, `+{truncated} linhas` se cortado). Edição do doc em trecho que o pipeline não tocou é puxada mesmo com o arquivo alterado (merge de 3 vias). `doc_stale[]` ou `kept_file[]` não vazios = o doc ficou para trás do arquivo — informativo; o doc NÃO é atualizado automaticamente (parágrafo abaixo).
- **Exit 1 (conflito)** — para cada `conflicts[]`: o arquivo mudou no repositório E no doc desde o último render, no MESMO trecho (`conflicts[].overlaps`), a edição do doc não pôde ser des-escapada com segurança (`conflicts[].unsafe`), ou o doc removeria a seção inteira / mais de 50% das linhas (remoção em massa). **Nada foi gravado nesse arquivo** (o outro pode ter sido puxado normalmente — seguir o exit 0 para ele). Apresentar no topo do resumo do gate o bloco `⚠️ CONFLITO doc × repositório — {file}: {reason}`, com `editor_changes.lines` (o que mudou no doc) e `pipeline_changes.lines` (o que mudou no arquivo), e a pergunta `manter arquivo` / `aplicar doc` — **com `conflicts[].apply_doc_blocked` presente (#10112: o trecho envolve destaque que o pipeline moveu/trocou por reorder/swap/promote), oferecer só `manter arquivo`**, mostrando o motivo e pedindo que o editor refaça a edição no destaque na posição nova (`--resolve doc` seria recusado: aplicaria o bloco antigo duplicado/revertido). A resposta do editor é gravada com `apply --resolve "{file}=arquivo@{resolve_token}"` (mantém o arquivo só nos trechos em conflito — edições do doc em trechos disjuntos são aplicadas e aparecem em `pulled[]`; vai para `kept_file[]` e o doc é atualizado pelo parágrafo abaixo) ou `apply --resolve "{file}=doc@{resolve_token}"` (o doc vence só nos trechos em conflito; o resto do pipeline fica — mesmo tratamento do `pulled[]` acima), com o `resolve_token` daquele conflito e o **mesmo** `--doc-export` já gravado (sem export novo, a menos que o editor diga que mexeu no doc de novo; no ramo `sim`, com `--final`): se o arquivo ou o doc mudou desde a pergunta, o token não bate e o conflito volta (apresentar de novo). Nunca resolver sozinho.

**O doc NÃO é re-renderizado a cada mudança do pipeline (#10078).** `ajustar` (§4d.1), cascata (§4d.1a), promoção/troca de destaque (§4d.1b), autofix do fact-check e `doc_stale[]`/`kept_file[]` não disparam mais o ciclo apply → render → substituir → `confirm`: substituir o doc exige exportá-lo antes (para não apagar o que o editor digitou), e o export só acontece na finalização. Uma chamada por slot trocado. **i.
