# Pasta `arquivo/` (#13610)

Referência de `/diaria-video-montagem`, lida sob demanda (#14040). Gatilho: um `[aviso]` do arquivamento, o editor pergunta por um arquivo que saiu da raiz de `{AAMMDD}/`, mídia offline no Premiere numa sequência antiga, ou migração de pasta antiga (`archive-video-versions.ts`). Citado em "Fluxo do dia, arquivos e retomada" do SKILL.md.

**Pasta `arquivo/` (#13610).** Na raiz de `{AAMMDD}/` fica só a versão vigente de cada arquivo; as anteriores vão para `{AAMMDD}/arquivo/` (movidas, nunca apagadas). Depois de `build`, `srt`, `preview` e `upload` que deram certo, o script faz isso sozinho: no Drive pela API (o modo API e o modo local que sobe pela API; o move preserva o id do arquivo) e no disco quando o out dir é a pasta da edição (o Neo). Fica o XML de maior `_V{n}` de cada família (cada variante é uma família: `horizontal_V{n}`, `_Vertical_V{n}`, `_Vertical_V{n}-guia`, `-trechos`, corte, o antigo `_Youtube_V{n}`), o SRT da versão desse XML, e todo asset com hash no nome (`_audio_tratado-…`, `_titulo_vertical…-…`, `_cta_card_…`, `_tela_…`, `_trecho_…`) que algum XML que fica na raiz referencia por `pathurl` (o vigente de cada família e todo `.xml` sem versão no nome, como o `… - montagem (importar no Premiere).xml`); asset sem referência fica só o mais novo da família. Nenhum asset sai quando algum desses XMLs não pôde ser lido ou não tem `pathurl`, quando um XML do `plan.json` ainda não aparece na listagem, ou quando há asset mais novo que todo XML da raiz (listagem do Drive atrasada). A prévia regravada é gravada (ou enviada) primeiro; só depois a anterior vai para `arquivo/`, e falha do ffmpeg ou do upload deixa a anterior na raiz. **Decisão do editor ("deixar só a última versão"): o asset que só um XML anterior usa vai para `arquivo/` junto, então uma sequência antiga já importada no Premiere pode abrir com mídia offline. Para recuperar, reconectar a mídia apontando para `{AAMMDD}/arquivo/` da edição (o arquivo está lá, com o mesmo nome).** Fora da regra, sempre: subpastas (`Final/`, `Editado/`, `Editados/`, `Projeto/`, `trechos/`, `legendas-vertical*/`), brutos (nome de câmera, `bruto_unido`) e arquivos sem versão nem hash no nome (roteiro, decupagem, `.docx`, `.pdf`, `_origem-brutos.json`). Nome repetido no `arquivo/` ganha ` (arquivado {data})`. A `arquivo/` nasce com a conta dona da pasta de vídeo, a diaria.editor (#13619, `publishing.video.archive_folder_owner`: o remote rclone `gdrive-diaria:` do `300`); sem ele (o Neo, rclone ausente) ou se ele falhar, o OAuth do projeto cria, com `[aviso]`, e essa pasta fica com o dono do OAuth. A numeração do `build` conta o `arquivo/` e a versão do `plan.json`: arquivar o V8 nunca faz o próximo build voltar a um V já importado (#13414). Falha ao arquivar é `[aviso]` e não muda o exit; `--no-archive` desliga. O `transcribe` e o `archive-video-brutos.ts` só olham arquivos soltos na raiz (e `Brutos/`), então nunca acham bruto no `arquivo/`. Migração das pastas antigas (absorve o `_superadas/` da 261110/261111): `npx tsx scripts/archive-video-versions.ts [--edition {AAMMDD}] [--json] [--verbose]` lista o plano (dry-run, o padrão); `--apply` move (exit 1 = alguma pasta falhou, com o que já foi movido no relatório; 3 = terminou com avisos; 4 = OAuth, config ou listagem); no Neo, `--local-root "I:/Meu Drive/diaria-studio-video"` opera no disco.
