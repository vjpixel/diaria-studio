# Capa no 1º frame do vertical do YouTube (#12100), desligada desde 17/11/2026

Referência de `/diaria-publica`, lida sob demanda (#14040). Gatilho: `publishing.shorts.youtube_first_frame_cover` voltou a `true`, ou um registro traz `vertical_feed: "first_frame_cover"`. Citado no Passo A2 do SKILL.md.

**Capa no 1º frame do vertical do YouTube: DESLIGADA desde 17/11/2026 (#12100, decisão do editor).** Duas medições no `oar2` deram frame automático (400 ms em Hkx35UI-XCM, distância 0,441; 1000 ms em 7OMVoFQNru8, 0,422), e o 7OMVoFQNru8 saiu com o áudio registrado pelo YouTube a ~2,4 kbps (#13403). Com `youtube_first_frame_cover: false` (o config atual), o `publish-shorts.ts` sobe o vertical original, loga `[premissa] youtube_shorts: capa no 1º frame desligada ...` e grava `vertical_feed: "manual"`; a capa vertical do feed fica só com o Passo B3a. O resto deste parágrafo é histórico, para quem religar a chave (#12100 opção 2, decisão de 11/11/2026; antes, ver a #13403): com `publishing.shorts.youtube_first_frame_cover: true` (o default do código quando a chave falta), o `publish-shorts.ts` sobe para o YouTube Shorts uma cópia do vertical com a capa nos primeiros `youtube_first_frame_cover_ms` (~1 s desde 16/11/2026, arredondado ao frame, com o valor efetivo no registro; com 400 ms a medição do 1º Short, Hkx35UI-XCM, deu frame automático no `oar2`; com áudio em silêncio; ffmpeg num diretório temporário, antes do marcador de envio e só com a credencial `YOUTUBE_*` presente; a saída é conferida pelo ffprobe), para o frame automático do feed (`oar2.jpg`) cair nela. O vertical da pasta da edição e o export do editor em `Final/` não mudam, e os outros destinos sobem o original. O log traz `[ok] youtube_shorts: arquivo preparado com a capa nos primeiros {N} ms ...`; falha do ffmpeg/ffprobe, saída que não confere (W×H, áudio, duração), duração desconhecida ou capa ausente/ilegível vira `[aviso]` e o Short sobe o original. `youtube_first_frame_cover_ms` inválido vira `[aviso]` e cai no default 1000. O registro passa a `cover: { method: "thumbnails_set", ok: true, vertical_feed: "first_frame_cover", first_frame_ms: 1000 }`: aplicado, **não confirmado**. Nunca relatar ao editor que o feed mostra a capa por causa disso. O Passo B3a continua valendo até a medição confirmar (o B3a troca só o `vertical_feed` para `"studio_web"`; o `first_frame_ms` fica, para saber qual Short levou a capa no 1º frame).

**Medição (encerrada em 17/11/2026 com as duas medições acima; o procedimento fica para quando a chave for religada: no 1º Short publicado com `first_frame_cover`, depois que ele ficar público e processado):** conferir o frame automático contra a capa local:

```bash
npx tsx scripts/check-short-feed-cover.ts --id {VIDEO_ID} --cover data/editions/{AAMM}/{AAMMDD}/04-youtube-short-capa.jpg --image oar2
```

Exit 0 = o `https://i.ytimg.com/vi/{VIDEO_ID}/oar2.jpg` é a capa (o 1º frame pegou); exit 1 = outro frame (não pegou neste Short); exit 2 = erro de leitura (404 no `oar2` = vídeo privado, inexistente ou ainda processando, tentar depois; o `oar2` existe em todo Short público e processado). O `oar2` não muda com a miniatura aplicada no Studio web (#12251), então a medição vale mesmo depois do B3a. Registrar o resultado (id, exit, distância) num comentário da #12100: é ele que decide se o B3a pode sair do fluxo ou se a opção é desligada (`youtube_first_frame_cover: false`).
