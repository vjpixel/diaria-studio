## Achado (review consolidado diário, range `34c61fb..42ddba9`)

O #8485 (PR #8485, commit `bbefa1011`) mediu ao vivo que `CHAR_WIDTH_RATIO = 0.52` subestima a largura real das linhas — "o rasterizador cai em serif mais larga que Georgia quando ela não está instalada, e 0.52 deixava linha vazar do card" — e introduziu `FILL_CHAR_WIDTH_RATIO = 0.62` (`scripts/lib/weekly-flat-card.ts:61`).

Mas a correção foi aplicada **só ao caminho `fill`** (`fillingFontSize`, `scripts/lib/weekly-flat-card.ts:365` e `:372`). O caminho `fixed` de `layoutCardBody` continua usando o `CHAR_WIDTH_RATIO` antigo:

```ts
// scripts/lib/weekly-flat-card.ts:337-339
size = layout.size;
const maxCharsPerLine = Math.max(1, Math.floor(availableWidth / (size * CHAR_WIDTH_RATIO)));
lines = wrapBody(title, maxCharsPerLine);
```

Horas depois, o #8480 (PR #8494, commit `593ac6c6c`) trocou a capa/CTA do carrossel SEMANAL de `fill` para `fixed` 84px (`WEEKLY_FLAT_CARD_LAYOUT`, `scripts/lib/weekly-flat-card.ts:259-260`, consumido em `scripts/publish-weekly-social.ts:1244-1245`). Ou seja: **as duas superfícies que o #8485 acabara de consertar voltaram, pelo #8480, a quebrar com a razão 0.52 que o #8485 mediu como errada.** Fix supersedido por outro PR do mesmo dia.

### Cenário de falha concreto

- `availableWidth = 1080 - 72*2 = 936`; `layout.size = 84`.
- `maxCharsPerLine = floor(936 / (84 * 0.52)) = 21` chars por linha.
- Largura real estimada dessa linha com a razão medida: `21 * 84 * 0.62 ≈ 1094px` — **~158px além dos 936 disponíveis**.

Uma capa/CTA cujo texto produza uma linha cheia (21 chars) sai com a linha vazando pela direita do card 1080×1350 publicado em Instagram/Facebook/Threads/LinkedIn.

### O guard novo não pega isso

O abort de overflow que o #8480 adicionou (`resolveOrGenerateFlatCardUrl`, `scripts/lib/weekly-flat-card.ts:603-613`) consome `measureFlatCardBody(...).overflows`, e `overflows` é **só altura**:

```ts
// scripts/lib/weekly-flat-card.ts:343-344
const blockHeight = lines.length * Math.round(size * 1.18);
return { ..., overflows: blockHeight > availableHeight };
```

Transbordo horizontal nunca é detectado — exatamente a classe de falha que o #8485 documentou. Compare com o caminho de notícia, onde o #8480 fez a coisa certa: `overlayTitleOverflows` (`scripts/gen-social-card-4x5.ts`) checa **largura** (`line.length * fontSize * wrap.ratio > availableWidth`).

### Fix sugerido

1. `layoutCardBody` no modo `fixed` deve usar a mesma razão conservadora do `fill` (ou uma razão por consumidor, explicitamente escolhida) — não o 0.52 que o #8485 já classificou como subestimado.
2. `layoutCardBody` deve reportar overflow de **largura** além do de altura, para o abort de `resolveOrGenerateFlatCardUrl` valer para o caso real.
3. Teste de regressão (#633): título que produza linha de 21 chars a 84px deve acusar `overflows: true`.

Atenção: mexer em `CHAR_WIDTH_RATIO` no modo `fixed` também muda o wrap do **carrossel diário** (`DAILY_CAROUSEL_BODY_SIZE`, 62px, mesmo caminho) — avaliar se a razão deve ser por consumidor (weekly vs daily), como o #8485 fez com `WEEKLY_OVERLAY_WRAP`, em vez de global.
