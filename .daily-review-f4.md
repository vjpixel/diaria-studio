## Achado (review consolidado diário, range `34c61fb..42ddba9`)

O #8438 (PR #8456, commit `e79d3c4ea`) criou o custom field `confirmou_via` para medir "clicou no botão de confirmar" de forma **ortogonal à origem de aquisição** — é literalmente a tese da issue: "um field que o worker escreve SEMPRE que o clique chegar com token válido — independente de origem" (`scripts/lib/shared/reativar-confirmou-via.ts:20-21`).

Na implementação, porém, o field é escrito dentro de `desired` (`workers/reativar/src/index.ts:806-808`), **antes** do filtro de origem do #8235, e portanto passa por ele:

```ts
// workers/reativar/src/index.ts:806-808
if (confirmedByToken && env.KIT_CONFIRMOU_VIA_FIELD) {
  desired[env.KIT_CONFIRMOU_VIA_FIELD] = REATIVAR_CONFIRMOU_VIA_VALUE;
}
// :814-817
let fields: Record<string, string> = desired;
if (existsAlready && Object.keys(desired).length > 0) {
  const current = await readKitSubscriberFields(...);
  fields = filterKitOrigemFields(desired, current);   // <-- confirmou_via entra aqui
```

`filterKitOrigemFields` (`workers/reativar/src/index.ts:945-956`) é cego ao tipo de campo: `if (current === null) return {}` — qualquer falha de leitura descarta **todos** os campos, `confirmou_via` incluído.

### Cenário de falha concreto

Contato Kit já existente (`existsAlready: true` — a população de reativação é por definição de assinantes que já existem) clica no botão com token assinado válido. O `GET /v4/subscribers/{id}` singular falha (timeout, 5xx da Kit, rate limit):

1. `readKitSubscriberFields` devolve `null`;
2. `filterKitOrigemFields` devolve `{}`;
3. **`confirmou_via` não é gravado** — a ativação prossegue normalmente, o assinante vira `active`, mas a medição do clique se perde;
4. `evaluate-brevo-diaria.ts` lê o field vazio e classifica como `self_confirmed_kit`;
5. o log emitido é `reativar_kit_origem_preservada` com `motivo: "leitura_falhou"` e `campos: [..., "confirmou_via"]` — ou seja, uma perda de **medição** aparece rotulada como **preservação de origem**, que é semanticamente outra coisa. Quem ler o log não conclui "perdi a medição do #8438".

O mesmo caminho descarta o field num 2º clique quando ele já está preenchido (`campo_preenchido`) — aí é inócuo, o valor já está lá.

### Fix sugerido

Manter `confirmou_via` **fora** de `desired`/`filterKitOrigemFields` e mesclá-lo em `fields` depois do filtro — é o único jeito de honrar o "independente de origem" que motivou a issue. Alternativa mais conservadora: passar uma allowlist de campos não-origem para `filterKitOrigemFields`.

Teste de regressão (#633): clique com token + `readKitSubscriberFields` devolvendo `null` deve ainda enviar `confirmou_via` no POST.

## Prioridade: P3

Só perde dado de medição num caminho de exceção (falha de leitura do GET singular) — nenhum assinante deixa de ser ativado, nenhum e-mail indevido sai. Mas é exatamente o cenário que faria a coorte medida do #8438 subestimar os cliques de botão, sem sinal legível de que isso aconteceu.
