# Allowlist de override pra a verificação POSITIVA de ferramenta em LANÇAMENTOS (#1968).
#
# validate-lancamentos.ts exige um sinal POSITIVO de produto (slug/título com
# verbo de lançamento, substantivo de produto, família de IA, ou número de
# versão) pra cada item de LANÇAMENTOS. Item sem sinal → not_a_tool → hard-block
# (exit 1, surfaçado no gate).
#
# Se uma FERRAMENTA legítima tiver slug/título atípico que não casa nenhum sinal
# (e o gate flagar como not_a_tool por engano), adicione aqui 1 SUBSTRING de URL
# por linha. Qualquer item de LANÇAMENTOS cuja URL CONTENHA a substring é tratado
# como ferramenta verificada (override).
#
# Linhas começando com `#` são comentário; linhas em branco ignoradas.
# Prefira a substring mais específica possível (domínio + path) pra não liberar
# demais. Ex (fictício):
#   exemplo.com/launches/ferramenta-sem-keyword
#
# Dois tipos de entrada (#11554):
#   - URL ESPECÍFICA (sem `/` no fim): diz "é ferramenta" E vale como
#     confirmação de título/escopo de item extraído de newsletter (#9292).
#   - PADRÃO DE CAMINHO (termina em `/`, ou só o domínio): diz só "é
#     ferramenta" para tudo sob o caminho. Item extraído de newsletter sob o
#     padrão continua exigindo summary + verify_verdict confirmados (#9250).
#
# A allowlist só impede o REBAIXAMENTO de LANÇAMENTOS para RADAR; não promove
# item que o categorizer pôs em outra seção.
#
# Desde #11530, post de blog/changelog/news oficial com verbo de lançamento ou
# disponibilidade no TÍTULO ("now", "available", "introducing", "agora",
# "disponível") já passa sem entrada aqui.
#
# Padrões de caminho por decisão do editor (28/10/2026, #11530): blog oficial
