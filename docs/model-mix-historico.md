Movido do `CLAUDE.md` no #14002. O mix vigente (#9003, que revisa o #8941 onde diverge) segue no `CLAUDE.md`, seção "Otimização de tokens"; estes três parágrafos registram as decisões que ele sucedeu. Modelo e effort citados aqui podem estar defasados: a fonte é o frontmatter de cada agent.

- **(Histórico #8941)** Opus 5.5 (`claude-opus-5-5`) + `effort: low`, decisão do editor #8941 (28/09/2026) — sucede os 7 agents que rodavam Sonnet 5/`medium`: `writer`, `writer-destaque` (D1/D2/D3, Etapa 2 — **tem eval de replay #8144**), `writer-monthly`, `social-writer` (**tem eval de replay #8144**), `social-curto`, `fact-checker`, `image-crop-reviewer`. Coordenadores: `/diaria-overnight` e `/diaria-continuo` também `claude-opus-5-5`/`low` (overnight → `claude-sonnet-5-5`/`medium` desde #9530, 03/10/2026: o effort dos implementadores decide a qualidade, 3× mais achados em `low`); `/diaria-develop` fica em `claude-opus-5-5`/**`medium`** (roda com o editor presente, mediando trade-offs ao vivo — não é redução de effort simétrica à dos dois primeiros). Nenhum pin de Sonnet sem `effort` explícito sobrevive no repo (#8941 fecha essa brecha, incluindo herança de effort de coordenador pra subagente).
- **Opus 5** (#4042, sucede o #1951) — `scorer-select` (chunked-parallel, #1611) e `analyst-monthly` (pipeline mensal). Decisão editorial pós-gate de julgamento holístico (seleção subjetiva, diversidade temática), volume baixo, alto impacto em CTR — #159. Ambos rodam com `effort: low` no frontmatter (#3218) — julgamento holístico não precisa de reasoning effort alto. Custo idêntico ao Opus 4.8 ($5/$25 por MTok), então a troca não tem delta de custo por token. O que **pode** mudar é o thinking: o default do MODELO inverteu (no 4.8, omitir o parâmetro significava rodar sem thinking; no Opus 5, omitir significa adaptativo). Se o harness do Claude Code não fixa `thinking` ao despachar subagente, esses dois passam a pensar por invocação — mais reasoning tokens. Isso não é verificável a partir do repo (é camada de harness); se aparecer salto de custo/latência só nesses 2 agentes, essa é a causa provável. Sem risco de erro em qualquer cenário: `thinking` desabilitado só é rejeitado acima de `effort: high`, e nenhum dos dois declara thinking. Rate limit do Opus 5 é bucket separado da família 4.x. **`orchestrator` não entra nesta lista**: o #3710 removeu `model:`/`effort:` do frontmatter dele — é playbook lido pelo top-level, não subagente dispatchado via `Agent`, então o modelo efetivo é o da sessão, não algo configurável ali.
